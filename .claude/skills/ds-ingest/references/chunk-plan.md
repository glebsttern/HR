# Фаза 2 — План порций + резюмируемый манифест

Цель: из переписи нарезать чтение каталога на **порции**, каждая из которых заведомо влезает в ответ MCP, и записать их в `ds/_scan/manifest.md` со статусами. Манифест — это журнал прогресса: при обрыве или падении продолжаем с места, готовые порции не перечитываем.

## Эвристика нарезки (от крупного шва к мелкому)

1. **По странице.** Если на странице компонентов умеренно (ориентир ≤ ~50 наборов) — вся страница это одна порция.
2. **По группирующему фрейму/секции.** Если страница большая, но разбита на секции (`Forms`, `Navigation`, ...) — каждая секция это порция. Естественный шов, заодно даёт готовую группировку для `components.md`.
3. **По окну индексов.** Если секции нет или одна секция всё равно большая — режем верхний уровень на окна по N штук: `[0..N)`, `[N..2N)`, ... Дефолт **N = 40–60** наборов на порцию.

Подгоняй N под токен-бюджет: набор с богатой матрицей вариантов и длинным description «тяжелее». Если сомневаешься — бери N меньше (40), пустую ёмкость дешевле добрать, чем ловить упавший вызов.

## Оценка веса порции (прикидка)

Грубо: одна строка каталога это ~`name + description(обрезанный) + 2-5 ключей матрицы + nodeId`. На ответ MCP ~25k токенов безопасно влезает в районе 40–60 таких записей. Поэтому дефолт окна — 40–60. Если в ДС матрицы огромные (10+ свойств) — снизь до 25–30.

## Выход: `ds/_scan/manifest.md`

Каркас — в `templates/manifest.md`. Заполненный пример:

```markdown
# Манифест внесения

**Источник:** <из source.md>
**Создан:** <ISO>   **Токен-бюджет порции:** ~25k (N=50)

## Variables (Фаза 3)
| # | Коллекция | Node ID | Ожидается перем. | Статус |
|---|---|---|---|---|
| V1 | Primitives | 9:1 | 320 | pending |
| V2 | Semantic | 9:2 | 140 | pending |

## Компоненты (Фаза 4)
| # | Порция (scope) | Node ID | Окно | Ожидается комп. | Прочитано | Статус |
|---|---|---|---|---|---|---|
| C1 | Components / Forms | 5:6 | — | 24 | — | pending |
| C2 | Components / Navigation | 5:7 | — | 12 | — | pending |
| C3 | Components / (без секции) | 1:2 | [0..50) | 50 | — | pending |
| C4 | Components / (без секции) | 1:2 | [50..100) | 50 | — | pending |
| C5 | Blocks (вся страница) | 3:4 | — | 45 | — | pending |

## Лог
- <ISO> создан план: 2 коллекции, 5 порций компонентов, ожидается ~181 комп.
```

## Правила

- Статусы только `pending` / `done`. Порция становится `done` лишь после успешного чтения **и** сверки счёта (Фаза 4).
- «Ожидается» берётся из переписи (`childComps` для секций, размер окна для индексных порций).
- Если в Фазе 4 порция не влезла — **дробим её здесь**: заменяем строку на две с меньшими окнами, обе `pending`, и продолжаем. Манифест всегда отражает реальную нарезку.
- Колонка «Прочитано» заполняется в Фазе 4 фактическим числом — это след для верификации.
- Не начинай Фазу 3/4, пока манифест не записан.
