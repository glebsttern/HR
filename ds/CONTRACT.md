## Главное правило

Любая задача на интерфейс (новый экран, форма, карточка, доработка) собирается строго через эту ДС: композиция существующих компонентов из `components.md` + существующие Variables из `foundation.md`. Прибитые цвета, размеры, радиусы, шрифты в обход Variables запрещены. Сборку выполняет скилл `ds-build`.

## Что значит «через ДС»

1. **Компоненты — только из каталога.** `ds-build` читает `components.md`, выбирает по описанию/матрице, вставляет инстансы по `Node ID`. Не рисует с нуля.
2. **Цвета — только через Semantic/Component Variables** из `foundation.md`. Прибитый hex запрещён.
3. **Типографика, радиусы, отступы — через Variables.**
4. **Auto Layout везде.** Top-секции экрана = FILL × HUG по умолчанию.
5. **Иконки — реальные инстансы из HR Icons** (https://www.figma.com/design/8sNZMKkRGJz5uxoke7pMUv/HR-Icons), не плейсхолдеры и не локальные векторы (п. 2 CLAUDE.md).

## Что делать, если нужного нет

Источник «корпоративная» — **HR Library править напрямую нельзя** в рамках этого скилла (read-only). Но HR Library — это проектный файл, которым команда управляет сама, поэтому дополнение делает тот, кто ведёт Figma-файл (дизайнер/владелец ДС), не `ds-ingest`:

- **Нет компонента:** завести в HR Library на странице «Components» → перезапустить `ds-ingest` → использовать. До этого — не выдумывать «похожий» компонент в коде/Figma-макетах.
- **Нет токена (например зелёной шкалы под бренд):** завести Primitive + Semantic alias в HR Library → перезапустить `ds-ingest` → использовать. Прибивать зелёный hex в обход Variables запрещено даже для устранения блокера бренда.
- Если нужен временный паттерн до правки ДС — `ds/patterns.md` с пометкой «локальный паттерн, не часть корпоративной ДС» + явный флаг владельцу ДС, не тихая замена.

## Синхронизация Figma ↔ ds/*.md

Индекс и Figma не должны расходиться.
- ДС поменялась (появились компоненты на странице Components, поменялась палитра и т.п.) → перезапустить `ds-ingest` (перечитать только изменившиеся порции, см. `ds/_scan/manifest.md`).
- Индекс руками без сверки с Figma не править. Если правка руками — пометить дату и причину прямо в файле.

## Что запрещено

- Прибитые цвета/размеры/радиусы/отступы там, где есть Variable.
- Создание компонента «на лету» в составе экрана вместо использования каталога (для этой ДС — вместо запроса компонента у владельца ДС + перезапуска `ds-ingest`).
- Правки в файле HR Library без согласования с владельцем ДС.
- Сборка макетов вне HR Site (см. CLAUDE.md, жёсткое правило 1) — HR Library остаётся файлом ДС, макеты в него не заводятся никогда.
- Второй параллельный проект с собственной ДС в этой же папке.

## Когда правила можно нарушить

Только при явной команде «здесь без ДС, ad-hoc» (одноразовый рендер). Тогда отдельный фрейм, явно помеченный «ad-hoc, не часть продукта».
