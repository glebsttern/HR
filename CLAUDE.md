## Порядок работы

**Постранично и поблочно.** Страница доводится до готовности, прежде чем браться за следующую.

1. **Страница вакансий** — блоки по очереди: Хиро → Хедер → Список с фильтрацией → Форма → Преимущества → Футер.
2. Следующие страницы — после ретро по первой.

Для каждого блока цикл такой:
1. **Разбор.** Смотрю блок у Источника (что должно быть) и у Главного примера (как это устроено). Коротко пишу, что предлагаю.
2. **Согласование изменений в библиотеке** (см. ниже) — если блоку нужны новые компоненты или токены.
3. **Сборка на сайте.** При необходимости — черновик в HR Site.
4. **Проверка.** Десктоп 1660 и телефон 375, скриншоты, замеры вместо «на глаз».
5. **Ретро по блоку** (см. ниже).

## Правило согласования — главное

**Любое изменение в HR Library или HR Icons — только после твоего ответа.** Перед правкой я описываю:
- **что** добавляю или меняю (компонент, вариант, переменная, стиль);
- **зачем** — какому блоку нужно;
- **как** — варианты, токены, где ляжет на странице Components.

И жду реакции. Молча не добавляю даже «очевидное».

🚫 **Значения существующих переменных не меняю вообще** без прямой просьбы — это твоя зона. При расхождении подгоняю **код** под библиотеку, а не наоборот.

## Ретро — после каждого блока и каждой страницы

После блока — короткий разбор: что пошло не так, где потеряли время, что повторялось. Вывод — **правка этого файла или `ds/CONTRACT.md`**, чтобы следующий блок шёл проще и быстрее. Не пересказ сделанного, а изменение правил.

После страницы — ретро крупнее: пересматриваем порядок работы и набор скиллов.

Записи ретро — в `docs/HISTORY.md`, выводы — сюда, в разделы выше.

## Жёсткие правила Figma

1. **Макеты — только в HR Site.** HR Library — только дизайн-система.
2. **Иконки — только инстансы из HR Icons.** Нет нужной — предлагаю добавить её в HR Icons, не рисую в компоненте.
3. **Иерархия переменных: primitives → semantic → component.** Semantic — только алиасы primitives, component — алиасы semantic.
4. **Текст — только текстовыми стилями библиотеки** (`DS/Display/*`, `DS/Heading/*`, `DS/Body/*` …), не ручным кеглем и не привязкой к переменной размера.
5. **Цвета, радиусы, отступы — переменными; тени и блюр — стилями эффектов** библиотеки. Прибитых значений нет.
6. **Мобильная версия обязательна** для каждого экрана.
7. **Именование:** слои — PascalCase латиницей (русский только в тексте слоёв), варианты — `Property=Value`, переменные — `group/name`.
8. **После изменений в HR Library или HR Icons их нужно переопубликовать** — иначе HR Site и библиотека их не увидят. Напоминаю об этом явно.
9. **То, что ты внёс в HR Site вручную, не трогаю**, пока не попросишь.
10. **Перед удалением «лишнего» узла проверяю, не выпавший ли это вариант набора** (сверяю имя и число вариантов в наборе). Если выпавший — предлагаю вернуть, а не удалить.
11. **После массовой перекраски или перепривязки даю тебе короткий список, что проверить глазами** — какие компоненты, какие варианты, на что смотреть. Данные в Figma могут быть верными, а отрисовка — нет.
12. **Никогда не завожу компонент, который не привязан к стилям и переменным, без предварительного вопроса.** Каждый текст в компоненте — текстовым стилем библиотеки, каждый цвет, радиус и отступ — переменной, тень — стилем эффекта. Если подходящего стиля или переменной нет — сначала спрашиваю.

## Правила кода

- Next.js App Router, TypeScript, CSS Modules без Tailwind.
- Токены — `site/src/app/tokens.css`, тремя слоями, как в HR Library. Прибитых значений в компонентах нет.
- Компоненты в коде повторяют компоненты библиотеки: те же варианты и свойства. Форма собирается из компонентов, а не из локальной вёрстки.
- Факты о компании — только реальные (Источник, Сайт компании). Выдуманное наполнение помечаю ⚠️ в коде и здесь.
- Деплой: пуш в `main` → Vercel сам пересобирает (Root Directory = `site`).

## Скиллы — какой когда

| Когда | Скилл |
|---|---|
| Переснять состояние HR Library в `ds/` (только чтение) | `ds-ingest` |
| Собрать черновик в HR Site из библиотеки | `ds-build` |
| Разобрать приём у Главного примера | `design-decompose`, `explain-interface`* |
| Навести порядок на странице Components, выровнять блок | `better-layout` |
| Шрифты, шкала, переносы | `better-typography` |
| Цвета, палитра, контраст, имена токенов | `better-colors` |
| Мелкая полировка UI: скругления, выравнивание, зоны нажатия | `better-ui` |
| Анимация, переходы, ощущение от интерфейса | `emil-design-eng` (подробнее), `better-ui` (быстрые правила) |
| Доступность | `better-accessibility` |
| Тексты интерфейса | `better-writing` |
| Все проверки `better-*` разом | `better-interface` |
| Разбор готового блока перед ретро | `interface-review`* |
| Компонент во всех состояниях и крайних случаях | `break`* |
| Несколько вариантов блока на выбор | `variant`* |
| Интерактивы реально работают | `flow-to-app` |
| Нет ли типовых «нейросетевых» паттернов | `design-anti-slop` |
| Карта переходов перед новой страницей | `ia-first` |
| Индекс `ds/` → React + Storybook | `ds-to-storybook` |

\* — запускаешь ты командой (`/interface-review` и т.п.).

Скиллы лежат в `.claude/skills/` и в репозиторий не попадают (папка в `.gitignore`).

## Где что лежит

- `docs/HISTORY.md` — хронология и записи ретро.
- `site/` — код сайта.
