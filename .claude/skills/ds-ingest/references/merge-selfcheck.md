# Фаза 5 — Слияние и self-check

Когда все порции в манифесте `done`, каталог собран по кускам. Теперь привести его к единому виду и честно показать дыры. Это не косметика: индекс уходит в работу сборки, дыры там дорого всплывают.

## Слияние

- Проверь, что все строки манифеста (Variables и компоненты) в статусе `done`. Если есть `pending` — вернись в Фазу 3/4, не закрывай скилл.
- Сведи разделы `ds/components.md`: одинаковые секции из разных порций объединить под один заголовок, порядок разделов привести к стандартному (Действия, Ввод, Контейнеры, Навигация, Фидбэк, Данные, Прочее, Особенные).
- Сверь итог: сумма «Прочитано» по всем порциям должна совпасть с числом строк в `components.md` и с «Итого» из переписи. Расхождение — в отчёт.

## Дедуп

- **Дубли имён:** два набора с одним именем — конфликт, при сборке возьмётся первый. Пометь явно оба Node ID.
- **Старые версии рядом с новыми:** имена вида `Button old`, `Button v1`, `Card (deprecated)` — пометь как кандидатов на исключение, не удаляй из каталога молча.

## Self-check (статистика дыр)

Пройди по собранному `components.md` и `foundation.md`, посчитай:

- % компонентов с пустым `Назначение` (не было description). Больше 30% → жёлтый флаг, нужна ручная доводка.
- Наборы с пустым `componentPropertyDefinitions` — одиночки без вариантов (норма) или забытая настройка (проблема). Пометь.
- Подозрительные имена: `Component 1`, `Frame 234`, `Untitled` — в замечания, проверить у автора ДС.
- Variables: плоская коллекция без Semantic-слоя? Кириллица у `font-sans` (при ru/ru+en)? Дубли имён переменных?

## Короткий честный отчёт

```
ДС внесена порциями.
- foundation.md — <C> коллекций, <K> переменных
- components.md — <T> компонентов в <S> разделах (порций: <P>, все done)
- Сверка: перепись <T_census> == каталог <T> ✓ / расхождение <...>

Замечания (доводка после внесения):
- <пустые описания: X%>
- <дубли / старые версии: ...>
- <плоская коллекция Variables / кириллица: ...>
```

Внесение — стартовая точка, а не финал. Доводка описаний делается руками в `ds/components.md` (не в Figma).

## Обновление индекса (повторный прогон)

ДС живёт. Когда она поменялась:
- Перезапусти скилл. Заново сделай перепись → сравни с прошлым `census.md` (diff по счётчикам и именам).
- Перечитывай **только изменившиеся** порции: где счётчик/имена расходятся — ставь их в манифесте обратно в `pending`, остальные оставь `done`.
- Перепиши затронутые разделы `components.md` / слои `foundation.md`. В логе манифеста отметь дату и что обновилось.
- Не правь индекс руками без сверки с Figma: следующий прогон затрёт. Если правка руками всё же нужна — пометь дату и причину.
