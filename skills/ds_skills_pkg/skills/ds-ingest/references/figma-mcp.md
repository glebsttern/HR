# Фаза 0 — Figma MCP, доступ и токен-бюджет

Самодостаточный справочник: подключение MCP, какие read-инструменты используем для внесения, и как держаться в пределах лимита ответа.

## Подключение MCP (если ещё не подключён)

**Всегда через правку `~/.claude.json`.** Не вызывай `claude mcp add` — CLI может отсутствовать (агент часто внутри VSCode-расширения).

1. Прочитай `~/.claude.json`. Если нет доступа — попроси добавить read/write allow-правило на `~/.claude.json`.
2. В объекте `mcpServers` (верхний уровень) добавь:
   ```json
   "figma": { "type": "http", "url": "https://mcp.figma.com/mcp" }
   ```
   Если `figma` уже есть — не перезаписывай молча, покажи текущее и спроси.
3. Попроси перезапустить расширение/приложение Claude Code и написать «готово».
4. Попроси ссылку на любой фрейм (правый клик → Copy link to selection), вызови `get_design_context` — первый вызов триггерит OAuth, в чате появится ссылка авторизации Figma. После «готово» вызови ещё раз, убедись что вернулось содержимое. MCP подключён.

## Какие инструменты используем при внесении

Внесение — это **структурное чтение через `use_figma`** (Plugin API), а не визуальные read-инструменты.

| Инструмент | Роль во внесении |
|---|---|
| `use_figma` | основной. Запускаем JS по Plugin API: считаем узлы, читаем `name/description/componentPropertyDefinitions/id`, читаем Variables. Всё лёгкое и плоское. |
| `get_design_context` | **не используем на ДС** (тянет визуал и дерево целиком, переполняет на больших файлах). Допустимо разве что один раз на этапе подключения для авторизации. |
| `get_variable_defs` | запасной способ снять токены из выделения, если Plugin API недоступен. По умолчанию берём Variables через `use_figma`. |

Почему `use_figma`, а не `get_design_context`: нам нужны **метаданные индекса** (имена, id, матрицы вариантов), а не отрисованное содержимое. Plugin API отдаёт ровно это и стоит копейки по токенам.

### Обязательные правила Plugin API (иначе первый вызов падает)

- **Перед `use_figma` загрузи гайд figma-use.** Если есть скилл `/figma-use` — вызови его; иначе прочитай MCP-ресурс `skill://figma/figma-use/SKILL.md`. В каждый вызов `use_figma` передавай `skillNames: "resource:figma-use"`.
- **Только async-методы.** `getLocalVariableCollectionsAsync()`, `getVariableByIdAsync()`, `getNodeByIdAsync()`. Синхронные (`getLocalVariables`, `getVariableById`, `getNodeById`) в dynamic-page режиме не работают.
- **Страницы грузятся лениво.** `page.children` пуст, пока страница не загружена. Для чтения нескольких страниц за вызов используй `await page.loadAsync()` — он грузит страницу **без** смены текущей. `setCurrentPageAsync` вызывай максимум один раз за вызов (а лучше не вызывай вообще для чтения, хватает `loadAsync`).
- **Возврат через `return`.** Агент видит только то, что вернул. `console.log` не виден.
- **Атомарность.** Упавший скрипт не выполняется вообще. При ошибке СТОП, читаем сообщение, чиним, повторяем.
- **Скорость обхода:** `figma.skipInvisibleInstanceChildren = true` перед `findAllWithCriteria`.

## Токен-бюджет ответа MCP (важно для порционности)

- У ответа MCP-инструмента есть **лимит** (в клиенте Claude по умолчанию порядка 25k токенов). Большой ответ обрезается или роняет вызов.
- Это **клиентская** настройка (`MAX_MCP_OUTPUT_TOKENS`), не лимит Figma. Поднимать её — решение пользователя, **не правим конфиг молча**. Если планируешь крупные порции, предложи поднять лимит заранее, до эфира.
- Независимо от лимита: размер каждой порции в Фазе 4 держим так, чтобы ответ заведомо влезал. Лучше больше мелких порций, чем один упавший вызов. Подробно — `chunk-plan.md`.
- «Figma режет на 3000 токенов» — миф, в доках Figma такого числа нет. У Figma MCP есть rate limits **по числу вызовов** (зависят от сида), поэтому не гоняем лишних вызовов: основной объём читаем за минимум порций.

## Доступ к источнику

- **Community-кит (shadcn, Material, и т.п.):** сначала **Duplicate to your drafts**, дальше работаем по ссылке на **свою копию**. Read-only публичного Community-файла теряет половину контекста.
- **Корпоративная ДС:** нужен просмотровый доступ к файлу.
- Вход — ссылка строго **на страницу Components** (правый клик по странице или фрейму → Copy link), не на корень файла. Если прислали корень — переспроси.

## Фиксация контекста: `ds/source.md`

Один файл-якорь. Заполняется до чтения:

```markdown
# Источник ДС

- Тип источника: своя / корпоративная / дублированная Community
- Название ДС: <напр. shadcn/ui kit>
- Ссылка (своя копия, страница Components): <URL>
- Локаль продукта: ru / en / ru+en
- Дата внесения: <ISO-дата>
- Заметки доступа: <Duplicate сделан / просмотровый доступ есть / ...>
```

Локаль важна: при ru/ru+en в Фазе 3 отдельно проверяем поддержку кириллицы шрифтом ДС.
