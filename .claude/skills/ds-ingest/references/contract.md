# Фаза 6 — Контракт ДС + указатель в CLAUDE.md

Без этой фазы индекс остаётся справочником, который сборка не обязана использовать. Контракт закрепляет: при любой задаче на интерфейс агент работает строго через внесённую ДС.

## 6.1 Создать `ds/CONTRACT.md`

Каркас — в `templates/CONTRACT.md`. Заполняется под тип источника (своя / корпоративная / дублированная Community). Ключевые правила:

1. **Компоненты — только из каталога.** Сборка читает `ds/components.md`, выбирает по описанию и матрице, вставляет инстансы по `Node ID`. Не рисует похожее с нуля.
2. **Цвета — только через Semantic Variables** из `ds/foundation.md`. Прибитый hex запрещён.
3. **Типографика, радиусы, отступы — через Variables.**
4. **Auto Layout везде.**

Раздел «что делать, если нужного нет» зависит от источника:
- **Своя / дублированная Community:** можно добавить компонент/токен в Figma-файл ДС, потом перезапустить `ds-ingest` (или дописать строку руками) и только потом использовать.
- **Корпоративная:** ДС править нельзя. Собрать паттерн из существующих; если нет — `ds/patterns.md` с пометкой «локальный паттерн, не часть корпоративной ДС» + запрос в команду ДС.

Раздел «синхронизация»: индекс и Figma не должны расходиться. ДС поменялась → повторный прогон `ds-ingest` (см. `merge-selfcheck.md`). Руками индекс без сверки не правим.

## 6.2 Указатель в корневом `CLAUDE.md` среды

Проверь `CLAUDE.md` в корне рабочей среды. Добавь блок (если ещё нет):

```markdown
## Дизайн-система

В среду внесена ДС через `ds-ingest`. Правила работы с интерфейсом — в `ds/CONTRACT.md`.
При любой задаче на экраны/формы/компоненты:
1. Прочитай `ds/CONTRACT.md`.
2. Прочитай `ds/foundation.md` и `ds/components.md` для актуальных токенов и каталога.
3. Действуй строго по контракту. Сборку выполняет скилл `ds-build`.
```

Если в корневом `CLAUDE.md` проекта уже есть блок про ДС — допиши явный указатель на `ds/` и на `ds-build`, не дублируя.

## 6.3 Финальный отчёт

```
ДС внесена и закреплена контрактом.

ds/
  source.md          — что вносили
  _scan/census.md    — перепись
  _scan/manifest.md  — порции (все done)
  foundation.md      — токены
  components.md      — каталог с Node ID
  CONTRACT.md        — правила работы с ДС
CLAUDE.md            — указатель на контракт

В Figma ничего не меняли (read-only).
Дальше сборка экранов: скилл ds-build по этому индексу.
```

## Правила

- Контракт обязателен, не опция.
- Сборку контракт адресует скиллу `ds-build`, а не этому скиллу. `ds-ingest` только готовит вход.
- Read-only по Figma сохраняется и здесь: контракт — это md, канвас не трогаем.
