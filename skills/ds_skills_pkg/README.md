# Скиллы для работы с большой дизайн-системой в Figma

Два скилла для Claude Code, которые позволяют скормить агенту большую дизайн-систему из Figma и собирать по ней экраны, не переполняя контекст и не сжигая токены.

## Зачем это

Если дать агенту всю Figma-библиотеку целиком, он захлёбывается: контекст переполняется, токены кончаются, экраны выходят неконсистентными. Эти скиллы решают проблему так: дизайн-систему один раз **вносят в компактный индекс** (карта + профили компонентов + токены), а дальше агент работает **с индексом, а не со всей Figma**. Поэтому быстро, дёшево и консистентно, независимо от размера системы.

## Что внутри

```
skills/
  ds-ingest/   — вносит существующую ДС из Figma в локальный индекс (ds/)
  ds-build/    — собирает экраны из этого индекса (+ светлая/тёмная тема, проверка)
```

- **ds-ingest** — порционно: сначала перепись (что внутри), потом план порций, потом чтение частями. На выходе папка `ds/` с токенами, картой компонентов, профилями и контрактом. Read-only по Figma.
- **ds-build** — читает индекс, показывает план композиции, после подтверждения собирает экран реальными инстансами компонентов с привязкой к семантическим токенам. Тему (light/dark) переключает одним движением, без пересборки.

## Что нужно

- **Claude Code** (расширение для VS Code / Cursor или десктоп).
- **Figma MCP** — подключается правкой `~/.claude.json` (инструкция внутри: `ds-ingest/references/figma-mcp.md`).
- Доступ к Figma-файлу вашей дизайн-системы. Если это community-кит — сначала продублируйте его к себе («Get a copy»).

## Установка

1. Распакуйте архив.
2. Положите папки `ds-ingest` и `ds-build` в `.claude/skills/` вашего проекта (или в `~/.claude/skills/` глобально):
   ```
   <проект>/.claude/skills/ds-ingest/
   <проект>/.claude/skills/ds-build/
   ```
3. Перезапустите Claude Code, чтобы он подхватил скиллы.

## Как пользоваться

1. Подключите Figma MCP (один раз) — см. `ds-ingest/references/figma-mcp.md`.
2. **Внести свою ДС:**
   > Внеси дизайн-систему из этого Figma-файла: `<ссылка на страницу Components вашей копии>`
   Появится папка `ds/` с индексом.
3. **Собрать экран:**
   > Собери экран `<какой>` из этой ДС.
   Агент покажет план композиции, после вашего «ок» соберёт его в Figma из реальных компонентов.
4. **Тёмная тема:**
   > Сделай тёмную копию этого экрана.

## Как это устроено (коротко)

- Индекс = карта системы. Агент держит в контексте лёгкую карту, а конкретный компонент тянет из Figma только в момент сборки (прогрессивное раскрытие).
- Цвета/радиусы — через семантические токены, поэтому экраны консистентны и тема переключается на уровне дизайн-системы, а не правкой каждого экрана.
- Скиллы универсальны: работают с любой Figma-ДС (своя, корпоративная, community-кит вроде shadcn/Material).

## Важно

- ds-ingest ничего не меняет в вашей Figma (только читает).
- Большие иконные библиотеки (тысячи глифов) скилл сознательно не индексирует — берёт иконку точечно при сборке.
- Если ДС обновилась — перезапустите ds-ingest, он перечитает только изменившееся.
