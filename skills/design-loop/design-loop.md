# design-loop — генерация + петля критики

Связка: **Claude Design** генерит быстро, **Claude Code** держит систему и критикует. Между ними — петля, которая доводит generic-результат до уровня референса.

## Часть 1 — Системный промпт (ДВА входа)
Системный промпт = **СТИЛЬ + ПРОДУКТ**. Это два независимых потока, которые соединяются здесь:
- **СТИЛЬ — «как выглядит»** → из `STYLE_GUIDE.md` (Слой B). Декомпозиция из студии.
- **ПРОДУКТ — «что рисуем»** → что за продукт, его разделы, сущности, термины, **список экранов**. Берётся НЕ из Dribbble, а из продукта.
  > **ОБЯЗАТЕЛЬНО спросить в начале этого шага: «Есть свой продукт?»**
  > - **Если да** — пользователь даёт PRD / документацию / ссылку / описание; проектируем строго под ЕГО продукт (его сущности, термины, экраны).
  > - **Если нет** — используем продукт, который виден на кадрах референса (что за приложение, экраны/сущности в шоте).
  > Никогда не выдумывать третий продукт молча. Не идти дальше, пока источник продукта не подтверждён.
  > **Экранов в промпт просим мало — 2 (максимум 3).** Цель этапа — поймать стиль и собрать каталог компонентов, а не нарисовать всё приложение. Два экрана генерятся быстрее, петля критики фокуснее, компоненты всё равно покрываются. Выбирать 2 самых показательных (обычно: overview-экран с героем + один детальный/активный), чтобы вместе они закрывали максимум компонентов.
  > Наполнение продуктовым контекстом — отдельная большая фаза (брифинг/research/PRD). В этом флоу она **на входе генерации**. Без неё AI рисует «красиво, но не про твой продукт».

Из этих двух собрать **системный промпт** для дизайн-генератора. Не «сделай красиво», а система:
- Продукт (что это, тон, разделы).
- 6 принципов стиля (один герой; монохром + один акцент <5%; стекло/глубина; воздух; тихая дата-виз; иерархия в 3 уровня).
- **Дизайн-токены** (цвета/радиусы/тени/типографика) явными значениями.
- Компоненты, layout-системы.
- Язык UI (на каком языке текст на экранах, формат чисел).
- DO/DON'T + формат вывода (артефакт React/Tailwind, размер, тема).
> Только Слой B (структура). Кинематографичный рендер (Слой A) — НЕ сюда, он для обложек через генератор картинок (Krea), а не для рабочих экранов.

Системный промпт собирается свежим под текущий STYLE_GUIDE + продукт; артефакты прошлых прогонов не переиспользуются.

## Часть 2 — Петля критики (сердце метода)
Первый прогон почти всегда **generic** (тёмный/светлый админ-дашборд «как у всех»). Это нормально. Дальше:
1. Скрин результата → в Claude Code.
2. **Аргументированный разбор по убыванию важности.** Не «сделай лучше» (пусто), а: *что* дёшево и *почему*, со ссылкой на принцип. Типовые провалы:
   - Плоскость (нет стекла/глубины) — ~70% скачка.
   - **«Дом-стайл генератора»** — выглядит «как всё, что обычно генерит модель»: дефолтный шрифт, радиусы 16–24px, Medium-веса лейблов, всё центрировано в плотную сетку, привычные бейджи/дивайдеры. Значит **композицию/метрики с исходника не угнали** — вернуть из STYLE_GUIDE явные веса, крупные superellipse-радиусы, воздух, асимметрию, щедрые отступы.
   - **Нарисованные бордеры/обводки** на карточках и кнопках — в реальных продуктах их почти нет; край держится СВЕТОМ (блик + тень + внутренняя люминесценция). Border-и-border = флэт-маркер → убрать.
   - Нет одного героя (всё равного веса).
   - Второй акцент / цветной акцент (разжижает; в «свет вместо цвета»-системах — особенно).
   - Герой-число без ремесла (перенос/вес/юнит/outline).
   - Фон без грейда; нет финиша (зерно/блики/ambient) → стерильно.
   - Типографика/дата-виз недожаты.
3. **Точная правка, а не общая.** Не «добавь глубины», а «градиент-заливка + блик по верхней кромке + тонированная тень + blur».
4. Выдать **готовый блок ревизии** (копи-пейст в генератор) → новый результат.
5. Повторять 1–3 круга. Сравнивать **до/после**.

Свод правил, на который опирается критика, — в STYLE_GUIDE текущего прогона (принципы + анти-паттерны + чек-лист) и в `emil-design-eng` (моушен/интеракции).

## Честная рамка (проговаривать)
Плоский рабочий UI ≠ кинематографичный рендер. Доведённое ремесло (глубина + иерархия + финиш) — потолок плоского экрана. «Вау как на обложке» — отдельный слой подачи (угол/боке/грейд), не гнаться за ним внутри живого UI.

## Память
- Подавать Claude Code как расширение для VS Code, не «терминал» ([[feedback_claude_code_framing]]).
- Курсив не использовать ([[feedback_no_italic]]).

## Выход
- Системный промпт под дизайн-генератор.
- Доведённые экраны + разбор «до/после».
- Готовность к хендоффу (`handoff-to-figma`).
