# ds-ingest — внесение объёмной дизайн-системы порциями

Превращает существующую ДС в Figma (свою, корпоративную или дублированную из Community, например shadcn) в компактный индекс `ds/`, который агент держит в контексте при сборке. Скилл заточен под **объём**: ДС может быть на сотни наборов компонентов и тысячи Variables, поэтому всё делается **порциями, с переписью наперёд и чекпойнтами**, чтобы не переполнить контекст и не упереться в лимит ответа MCP.

Скилл **самодостаточен**: несёт свой справочник по Figma MCP и свои инварианты. Среда на внешние скиллы не опирается.

## Главная ценность

Большую ДС нельзя читать «в лоб»: один запрос на весь файл переполняет контекст и режется лимитом MCP. Решение — читать **карту, а не территорию**, и **порциями**:
1. сперва дешёвая перепись (только счётчики и имена) → понимаем масштаб и швы;
2. план порций под токен-бюджет + манифест со статусами (резюмируемость);
3. чтение каждой порции лёгкими структурными вызовами (`id / name / description / матрица вариантов`), без визуала и без рекурсии в инстансы;
4. верификация счёта на каждой порции;
5. слияние, дедуп, честный self-check;
6. контракт, по которому дальше работает сборка.

На выходе `ds/foundation.md` + `ds/components.md` это лёгкая всегда-загружаемая карта, а `Node ID` позволяет сборке тянуть конкретный компонент только в момент нужды (прогрессивное раскрытие).

## Когда вызывать

- «Внеси / импортируй существующую дизайн-систему», «втащи ДС в среду» → весь поток ниже.
- «Просканируй большую ДС / этот Figma-кит», «сделай индекс UI-кита» → весь поток.
- «Обнови индекс ДС, она поменялась» → повторный прогон (см. `references/merge-selfcheck.md`, раздел про обновление).

Триггер-слова: «внести ДС», «импорт ДС», «просканировать дизайн-систему», «индекс UI-кита», «большая дизайн-система», «shadcn / Material / Carbon / корпоративная ДС в среду».

## Рабочая директория

Артефакты складываются в `ds/` **текущей рабочей среды** (откуда запущен Claude). В Figma **ничего не меняем** — скилл read-only.

## Поток (6 фаз, детали в references/)

Подгружай reference конкретной фазы по мере захода в неё, не все сразу.

0. **Пре-флайт и доступ** ([`references/figma-mcp.md`](references/figma-mcp.md)) — Figma MCP подключён; вход это ссылка на **свою дублированную копию** ДС, строго на страницу Components; зафиксировать источник/локаль в `ds/source.md`; помнить про лимит ответа MCP.
1. **Перепись** ([`references/census.md`](references/census.md)) — один лёгкий вызов: страницы, имена/типы верхнего уровня, счётчики наборов и одиночек, коллекции Variables с количеством. Выход: `ds/_scan/census.md`.
2. **План порций + манифест** ([`references/chunk-plan.md`](references/chunk-plan.md)) — режем по швам (страница → секция → группирующий фрейм), большое → окнами по N. Выход: `ds/_scan/manifest.md` со статусами pending/done.
3. **Foundation по коллекциям** ([`references/variables.md`](references/variables.md)) — Variables по коллекции, только имя/тип/значение/alias. Инкрементально пишем `ds/foundation.md`.
4. **Каталог по порциям** ([`references/components.md`](references/components.md)) — для каждой pending-порции один структурный вызов, дописываем `ds/components.md`, сверяем счёт, помечаем done. При переполнении дробим окно.
4b. **Глубокие профили** ([`references/deep-profiles.md`](references/deep-profiles.md)) — второй слой для качественной сборки: анатомия, слоты, полный набор вариантов/props, размеры. По категориям в `ds/components/<категория>.md`. Делать, когда нужны экраны (для простого индекса можно пропустить).
5. **Слияние и self-check** ([`references/merge-selfcheck.md`](references/merge-selfcheck.md)) — группировка, дедуп, статистика дыр, честный отчёт.
6. **Контракт** ([`references/contract.md`](references/contract.md)) — `ds/CONTRACT.md` + указатель в корневом `CLAUDE.md` среды.

## Инварианты (без исключений)

1. **Read-only по Figma.** Скилл ничего не создаёт и не меняет на канвасе. Никаких «давай заодно поправлю описания» в Figma. Доводка описаний — только в `ds/components.md`.
2. **Карта, а не дерево.** Снимаем только `id / name / description / componentPropertyDefinitions` (для компонентов) и `name / type / value|alias` (для Variables). Никакого `get_design_context` на больших выделениях, никакого визуала.
3. **Без рекурсии.** Верхний уровень страницы Components + максимум один уровень внутрь группирующих фреймов/секций. В инстансы и внутренности компонентов **не заходим** — это главная защита от взрыва контекста.
4. **Перепись до тяжёлого чтения.** Не начинаем читать каталог, пока нет `census.md`. Размер порции считаем от переписи, а не на глаз.
5. **Манифест ведёт прогресс.** Каждая порция отмечается done только после успешного чтения и верификации счёта. Готовые порции при перезапуске не перечитываются.
6. **Порция под токен-бюджет.** Если вызов рискует переполнить ответ MCP — уменьшаем окно и ретраим, прогресс не теряем. Лучше больше мелких порций, чем один упавший вызов.
7. **Верификация на каждой порции.** Фактический счёт прочитанного сверяется с ожидаемым из переписи. Расхождение — в замечания, не молча.
8. **Имена латиницей, описания по-русски.** В выходных файлах имена компонентов/токенов как в Figma (латиница), `Назначение` пишем по-русски (переводим существующий description).
9. **Без контракта скилл не завершён.** Без `ds/CONTRACT.md` и указателя в `CLAUDE.md` индекс остаётся справочником, который сборка не обязана использовать.

## Templates (заготовки артефактов)

## Связь с другими скиллами среды

- После внесения сборку экранов делает отдельный скилл `ds-build` (читает `ds/CONTRACT.md` + `ds/components.md` + `ds/foundation.md`). `ds-ingest` готовит для него вход.
