# DS Contract — правила работы с дизайн-системой в этой среде

**Источник ДС:** ds-ingest (<своя / корпоративная / дублированная Community>)
**Figma-файл:** <ссылка на страницу Components>
**Дата внесения:** <ISO>

## Главное правило

Любая задача на интерфейс (новый экран, форма, карточка, доработка) собирается строго через эту ДС: композиция существующих компонентов из `components.md` + существующие Variables из `foundation.md`. Прибитые цвета, размеры, радиусы, шрифты в обход Variables запрещены. Сборку выполняет скилл `ds-build`.

## Что значит «через ДС»

1. **Компоненты — только из каталога.** `ds-build` читает `components.md`, выбирает по описанию/матрице, вставляет инстансы по `Node ID`. Не рисует с нуля.
2. **Цвета — только через Semantic Variables** из `foundation.md`. Прибитый hex запрещён.
3. **Типографика, радиусы, отступы — через Variables.**
4. **Auto Layout везде.** Top-секции экрана = FILL × HUG по умолчанию.
5. **Иконки — реальные SVG** из библиотеки ДС, не плейсхолдеры.

## Что делать, если нужного нет

### Источник «своя» / «дублированная Community»
- **Нет компонента:** добавить в Figma-файл ДС → перезапустить `ds-ingest` (или дописать строку в `components.md` руками) → потом использовать.
- **Нет токена:** добавить Variable в Semantic с alias к примитиву → дописать в `foundation.md` → использовать.

### Источник «корпоративная» (ДС править нельзя)
- Собрать паттерн из существующих компонентов.
- Если действительно нет — `ds/patterns.md` с пометкой «локальный паттерн, не часть корпоративной ДС» + запрос в команду ДС.

## Синхронизация Figma ↔ ds/*.md

Индекс и Figma не должны расходиться.
- ДС поменялась → перезапустить `ds-ingest` (перечитать только изменившиеся порции, см. manifest).
- Индекс руками без сверки с Figma не править. Если правка руками — пометить дату и причину.

## Что запрещено

- Прибитые цвета/размеры/радиусы/отступы там, где есть Variable.
- Создание компонента «на лету» в составе экрана, если его можно собрать из существующих или вынести в ДС (для своей/дублированной).
- Правки в файле корпоративной ДС без согласования.
- Второй параллельный проект с собственной ДС в этой же папке.

## Когда правила можно нарушить

Только при явной команде «здесь без ДС, ad-hoc» (одноразовый рендер). Тогда отдельный фрейм, явно помеченный «ad-hoc, не часть продукта».
