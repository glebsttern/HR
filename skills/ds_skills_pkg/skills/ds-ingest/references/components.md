# Фаза 4 — Каталог компонентов по порциям

Цель: для каждой `pending`-порции из манифеста снять лёгкий структурный срез верхнего уровня и дописать строки в `ds/components.md`, сверить счёт, пометить порцию `done`. Это самая объёмная фаза, здесь и живёт защита от переполнения.

## Чтение порций (с `loadAsync`, async API)

Можно прочитать **несколько страниц-порций за один вызов** через `await page.loadAsync()` (грузит страницу без смены текущей). НЕ используем `setCurrentPageAsync` в цикле и НЕ читаем `page.children` до загрузки.

```js
figma.skipInvisibleInstanceChildren = true;
const ids = ["<page id>", "..."]; // батч страниц-порций из манифеста
const out = [];
for (const id of ids) {
  const page = await figma.getNodeByIdAsync(id);
  if (!page) { out.push({ id, error: "not found" }); continue; }
  await page.loadAsync();

  const sets = page.findAllWithCriteria({ types: ["COMPONENT_SET"] }).map(n => {
    let props = null;
    try {
      const d = n.componentPropertyDefinitions;
      if (d) props = Object.fromEntries(Object.entries(d).map(([k, v]) =>
        // Figma добавляет к ключам суффикс #id — срезаем; для VARIANT берём варианты
        [k.replace(/#.*$/, ""), v.variantOptions ? v.variantOptions.join("|") : v.type]));
    } catch (e) {}
    return { name: n.name, id: n.id, desc: (n.description || "").slice(0, 140), props };
  });

  // standalone COMPONENT = НЕ variant-ребёнок набора
  const singles = page.findAllWithCriteria({ types: ["COMPONENT"] })
    .filter(c => !c.parent || c.parent.type !== "COMPONENT_SET")
    .map(n => ({ name: n.name, id: n.id, desc: (n.description || "").slice(0, 140) }));

  out.push({ page: page.name, id, setCount: sets.length, singleCount: singles.length, sets, singles });
}
return out;
```

**Параллелизм:** можно эмитить несколько таких `use_figma`-вызовов в одном сообщении (разные батчи id) — они выполняются конкурентно. Каждый вызов держи в рамках бюджета ответа (см. ниже).

**Что НЕ делаем:** не заходим в `INSTANCE`, не читаем внутренности компонентов/наборов, не дёргаем `get_design_context`, не снимаем визуал. Только метаданные. `desc` срезаем (140), ключи матрицы чистим от `#id`-суффикса.

**Если структура «одна страница Components со всем»** (а не страница-на-компонент): грузим эту страницу, и вместо списка страниц режем `page.children` окном `slice(from,to)`; в группирующие FRAME/SECTION заходим на один уровень за `COMPONENT_SET`/`COMPONENT`, не глубже.

## Защита от переполнения

- Если ответ обрезан/вызов упал — порция **слишком большая**. Не считаем её прочитанной. Идём в `chunk-plan.md`: дробим строку манифеста на два меньших окна (обе `pending`) и читаем по очереди.
- Признак риска заранее: набор с матрицей из многих свойств и длинным description. Для таких секций бери окно поменьше.
- `desc` всегда обрезаем (160 симв.), `props` пишем только ключами + значениями вариантов, не разворачивая все комбинации.

## Запись в `ds/components.md`

Формат — по `templates/components.md` (таблицы по разделам). Пиши **инкрементально**: каждая порция дописывает свои строки в соответствующий раздел (`section` из чтения). Группировку бери по `section`; если секции не было — раскладывай по смыслу из имени/описания (Действия, Ввод, Контейнеры, Навигация, Фидбэк, Данные, Прочее).

Строка каталога:

```markdown
| `Button` | ComponentSet | `1:234` | `type: primary\|secondary\|ghost; size: sm\|md\|lg` | — | Основная кнопка действия |
```

- `Node ID` обязателен — по нему сборка тянет компонент.
- Матрица компактно: `key: val1 | val2`, не таблица из 24 комбинаций.
- `Назначение` по-русски: из `description` (перевести) или кратко по имени (и пометить в замечаниях, что описания не было).

## Верификация порции (обязательно)

После записи порции:
1. Сверь `readCount` с «Ожидается» из манифеста для этой порции.
2. Совпало → впиши `readCount` в колонку «Прочитано», статус `done`, добавь строку в Лог.
3. Не совпало → разберись (группа содержала не-компоненты? окно перекрылось с соседним?), при необходимости поправь нарезку. Не помечай `done`, пока не сойдётся или расхождение не объяснено в логе.

## Резюмируемость

- При перезапуске скилла читай манифест: порции `done` пропускаешь, берёшь первую `pending`.
- Никогда не перечитывай `done`-порцию без явного запроса (обновление ДС — отдельный сценарий, см. `merge-selfcheck.md`).
